# Routage institutionnel

## Principe

Le projet est transversal. Il ne faut donc pas supposer qu'un seul dicastère ou service peut en être propriétaire.

Les fonctions concernées sont différentes :

| Besoin | Compétence pertinente |
|---|---|
| Statuts doctrinaux | théologie / doctrine |
| Histoire des idées | histoire de l'Église |
| Éditions et métadonnées | bibliothèques / archives |
| Déploiement et sécurité | informatique |
| Interface publique | communication |
| Culture, humanités, sciences | culture et éducation |
| Gouvernance d'une édition institutionnelle | combinaison de plusieurs rôles |

## Premier contact

Préférer :

- un destinataire principal pertinent ;
- au maximum un ou deux CC ayant une raison fonctionnelle claire.

Éviter un envoi massif. Le contraste avec des communications antérieures doit être visible : cette fois, il s'agit d'un artefact précis, pas d'une campagne générale.

## Handoff interne souhaité

La phrase la plus utile est :

> « Si ce sujet relève d'une autre personne ou d'un autre service, vous pouvez simplement lui transférer ce message. »

Le paquet doit être autoportant : une personne qui le reçoit après transfert doit comprendre le projet sans avoir l'historique du fil.
